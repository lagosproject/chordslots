## P4.2 — real corpus pipeline (commit "Prior: build transition statistics from Billboard and RS200")
Rewrite `tools/build_corpus.py`. **Delete the hand-authored count tables entirely.**
1. Usage: `python3 -I tools/build_corpus.py --data third_party/chord-data [--verify] [--out …] [--counts-out tests/corpus_counts.json]`.
   Without `--data`, `--verify` prints "corpus data not available, skipping" and exits 0
   (CI has no data; the committed `Corpus.h` is the artefact).
2. **Checksums:** before reading, verify the SHA-256 of `raw/choco-v1.0.0.zip` and
   `raw/rs200_harmony_clt.zip` against values pinned in the script (from SOURCES.txt). On a
   mismatch, stop with an error.
3. **Billboard parsing:** read the Harte labels and parse root, shorthand, extensions in
   parentheses (including `*`-omitted ones) and `/bass` into a pitch-class interval set.
   Support at least: maj, min, dim, aug, maj7, min7, 7, dim7, hdim7, minmaj7, maj6, min6,
   9, maj9, min9, 11, min11, 13, maj13, min13, sus2, sus4, 5, and 1 (single note), with
   extensions such as `(9)`, `(b7)`, `(#9)`, `(b7,9)`, `(*3)`. Then classify it with the **same
   rules as `qualityClassFromIntervals` in `Theory.h`** (port them to Python). Label `1`,
   unparseable labels and `N`/`X` **break the chain**: never count a transition across them.
   Collapse consecutive identical chord tokens (a repeat is not a transition).
   Degree = (root − tonic) mod 12 using the `key_mode` tonic.
4. **RS200 parsing:** use column 4 (chromatic root relative to key) as the degree. Take the
   quality from the Roman numeral (upper-case = major, lower-case = minor, `o`/`x` =
   diminished, `h7`/`ø` = half-diminished, `d7` or `V7`-type dominant sevenths = Dominant,
   `+` = augmented). Document each mapping rule in the code with an example. Key changes
   are already relative per chord. Collapse repeats.
5. **Song mode** (both sources): a song is **minor-mode** if, among chords on degree 0,
   minor-class chords outnumber major-class plus dominant-class ones; otherwise major-mode.
   Songs with fewer than 3 tonic chords: decide by degree-0 vs degree-9 weight (relative
   major/minor). Report how many songs end up in each mode.
6. **Clusters** (keep the 3 matrix slots and the `CorpusStyle` enum values, so saved
   states stay valid):
   - slot 0 (`PopRock`) = all major-mode songs,
   - slot 1 (`MinorLoops`) = all minor-mode songs,
   - slot 2 (`SoulRnb`) = **extended-harmony songs**: songs where ≥ 30% of chord tokens
     are 7ths/9ths/11ths/13ths (any quality), with both modes merged. Billboard has no
     genre labels, so this is the honest data-driven stand-in. Report the song count and
     transition count per cluster. If slot 2 has fewer than 40 songs, lower the threshold
     to 25% and say so.
7. **Smoothing:** keep the P1 interpolated backoff formula
   (`λ_A = row/(row+β)`, `P = λ·ML + (1−λ)·P_uni`, `score = −ln P`), and the per-cluster
   0..255 quantization. β becomes a script parameter: try β ∈ {50, 200, 800} and pick one
   with a stated reason (e.g. held-out log-likelihood on a random 10% of songs, seed 0).
   Report the numbers.
8. Emit `Corpus.h` with the provenance header: sources, checksums, song counts per
   cluster, transition counts, β, script hash. Also write `tests/corpus_counts.json`
   (raw transition counts per cluster as sparse token pairs). This is derived data and
   covered by DATA_LICENSES.md.
9. **Cross-check test:** the script writes, for each of the 32 ChordSlots chord types (read
   their interval sets from `Theory.h` by parsing the `chordTypes()` table), the Python
   quality class. Add a C++ test that `qualityClassOf(type)` matches that list (fixture
   committed in `tests/`).
10. Keep the existing P1.1 C++ tests (seen < unseen in every row with counts, Am→C# more
    expensive than Am→F/G/Dm/Em, C→C# more expensive than C→F/G/Am). They must still pass on
    real data. If one fails, report it; do not weaken it without explaining why the data
    disagrees.
