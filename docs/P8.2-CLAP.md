# P8.2 CLAP build and validation

JUCE 9.0.5 does not provide a native CLAP format. The optional target uses the MIT-licensed
`free-audio/clap-juce-extensions` source pinned to `3837f4a6ed2ab0ba46aba69ae5b7041c7c64ce74`
(version 0.1.0), with its recursive `clap` and `clap-helpers` submodules. Ordinary builds do not
fetch the adapter.

Enable CLAP explicitly when needed:

```powershell
cmake -S . -B build-clap -A x64 -DCHORDSLOTS_BUILD_CLAP=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-clap --config Release --target ChordSlots_CLAP
```

For offline builds, pass CMake's standard source override with the recursive checkout at the pinned
revision:

```powershell
cmake -S . -B build-clap -A x64 `
  -DCHORDSLOTS_BUILD_CLAP=ON `
  -DFETCHCONTENT_SOURCE_DIR_CLAP_JUCE_EXTENSIONS=C:/deps/clap-juce-extensions
```

The adapter reports one CLAP MIDI note input and one output because the processor returns
`acceptsMidi() == true` and `producesMidi() == true`. Incoming CLAP note/MIDI events are added
to JUCE's input `MidiBuffer`; outgoing JUCE MIDI messages are forwarded to the CLAP output
queue.

Validate the resulting library with `clap-validator` 0.4.1:

```powershell
clap-validator.exe validate build-clap/ChordSlots_artefacts/Release/CLAP/ChordSlots.clap
```

With `CHORDSLOTS_BUILD_CLAP=ON`, CTest also runs `clap_midi_smoke`. It loads the actual `.clap`
through `clap_entry`, checks one MIDI-dialect note input and output, injects the default C3 trigger,
and verifies generated MIDI note-ons and note-offs reach the host event queue. CI should validate
the `.clap` with the pinned `free-audio/clap-validator` 0.4.1 asset and archive the exact
`ChordSlots_artefacts/Release/CLAP/ChordSlots.clap` file (MSVC places sibling `.lib`/`.exp` files
beside it). The host smoke supplements validator's generic compatibility checks.
