# Interactive listening test

**To run a session: open `tools/listening/listening-test.html` in Chrome or Edge (double-click). That is all.** Everything is inside that one file: the 100 sound files, the trial order and the questions. Nothing is uploaded and no sheets or folders are needed.

## What the listener does

1. Opens the page. A random participant ID is already filled in (kept in the browser; a facilitator can type a number such as 3 instead). Picks training and production experience, presses Start. "Try a sample first" plays a C chord then C7 (not recorded).
2. Four parts, with a short intro before each: tritone pairs (5 trials), Brightness pairs (23), single-loop ratings (24), mood pairs (13). About 45 to 60 minutes, not measured yet. Each trial: Play, first loop, 3 s of silence, second loop, one replay allowed (logged as `replayed`). Progress is saved after every answer; reopening with the same ID resumes.
3. "Stop here and get my answers so far" is on every trial screen: partial answers are kept and are still used (a participant counts once at least half the trials are answered).
4. At the end: "Download my results (1 file)" (`chordslots_results_<ID>.json`) or "Copy results as text" to paste into a message. Four separate CSVs are under "Other formats".

Answer order: digit IDs alternate A/B with the number (consecutive numbers balance it exactly); random IDs get a hashed orientation, balanced only in expectation. Each participant gets a shuffled order and one repeated, reversed pair as a consistency check.

## Publishing and collecting

Build with the place to send results shown to listeners: `python3 tools/listening/test-page/build_page.py --contact "you@example.org"`. The page is a static file (GitHub Pages, any host, or just emailed). There is no server: results come back by email or message. Then:

```
python3 tools/listening/import_results.py FILE...     # validates, writes tools/listening/data/<kind>/<kind>_<ID>.csv
python3 tools/listening/recompute.py                  # all analyses, with the minimum-N rule
```

`recompute.py` reports "trend only" below 5 participants, warns when nobody has music-theory training, and honours `data/EXCLUDE.txt` (for example the pilot). The rules were fixed before any data. See `data/README.md`.

### Hosting on GitHub Pages (this repo)
`build_page.py --docs --contact "..."` also writes `docs/listening-test.html`. After pushing, in the repo Settings > Pages choose "Deploy from a branch", branch `main`, folder `/docs`; the page is then at `https://lagosproject.github.io/chordslots/listening-test.html`. Everything in `docs/` becomes public on that site. Results come back as pasted text in a public issue (anonymous: random ID, training, answers) or by any other route you put in `--contact`.

## Producer mode
A checkbox on the first screen. After both answers of a pair are given, two draggable chips appear ("Loop 1", "Loop 2") that drag the `.mid` out under a neutral name (`loop_0207_1.mid`), plus download links as a fallback. A drag is logged as `dragged` in `notes`. It uses Chrome's `DownloadURL` drag type; whether Ableton accepts a drop straight from the browser is not verified, so try one drag first (dropping onto Explorer and then into Ableton also works).

## Sound
The page plays the `.mid` files with a small built-in additive synth: identical for every listener, not a real piano. Optional, under "Advanced" on the first screen: pick a folder of rendered `.mp3`/`.wav` files named like the stimuli (for example `pair05_A.mp3`); those are used where names match.

## For the maintainer

`test-page/template.html` is the source; `listening-test.html` is generated by `python3 tools/listening/test-page/build_page.py` (run it again after regenerating any stimuli, then commit both). The page contains only neutral identifiers (pair ids, file names, the mood word of part 4, item ids); what A and B mean stays in the operator keys used by the analysis scripts. File names do show which letter is which, but not what the letters mean.
